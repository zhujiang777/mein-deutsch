配套文档：`docs/a1-panorama.md`（格子定义）· `docs/course-authoring.md`（数据约定）

## 一、形式固定，难度靠材料 —— 不要把两者绑在一起

**曾经的误区**：以为"精听（盲听→大意→听写→复听→复述）是高阶活动，初学者只能听单句"，
于是想按能力层设计不同的活动类型。**这是错的。**

盲听→大意→听写→复听→复述 这套形式在**任何水平都成立**。
一份 3 句话、每句 5 个词、100% 已知词的对话，零基础者能走完整套流程，而且收获很大。

现有精听显得"高阶"，只是因为包是 10–20 句、已知词 37%——**是材料难，不是形式难。**

**结论**：不为每个能力层设计新活动，只维护 **固定的几种形式 + 一个分级的材料库**。

| 形式 | 练什么 | 难度旋钮 |
|---|---|---|
| 认词 / 词卡 | 词形—词义—发音 | 词频、是否同源 |
| 造句 / 微步课 | 语法产出 | 句长、需要的格子数 |
| 精听 | 从声音里切出词 | **句数、句长、已知词率、语速** |
| 精读 | 从文字里取信息 | **词数、已知词率、语法边界** |
| 说 | 发音与流利度 | 目标音数量、句长 |

破冰期第一天就可以有精听——只是那份材料是三句话。

## 二、发音课：三种"讲解"，只有第三种是关键

用户反馈"全是文字看不下去"，但**去掉讲解只做跟读也不行**——
多邻国就是纯跟读，学习者不知道自己读错在哪。

| 讲解类型 | 出现时机 | 形态 | 是否放主路径 |
|---|---|---|---|
| 陈述式（ch 有两种读法…） | 学之前 | 成段文字 | ❌ 降级为末尾"规则表"，回头查用 |
| **动作指令** | 每张卡开头 | **一行，≤20 字** | ✅ |
| 对比示范 | 学的时候 | 正确/错误两段音频并排 | ✅ 最有效，且不是文字 |
| **诊断式** | 读错之后 | 错在哪 + 一条修法 | ✅ **这才是多邻国做不到的** |

### 技术现实：音素级分数对德语拿不到

`worker/src/index.js` 用 `Granularity: 'Word'`，注释写明 de-DE 不返回可解释的音素名，
且开启 Phoneme 粒度会偶发丢掉整个评分区块。归一化后的 `words[].phonemes` 在 REST 路径上通常是空的。

**所以不能靠机器说"你的舌位太后"。**

### 不做"错音诊断表"——猜出来的诊断比没有诊断更糟

曾计划：每格人工写 2–3 条典型错读，词级分低时弹最可能的一条。**否决。**

读砸 `ich` 可能是读成 ish、读成 ik、元音不对，也可能只是含混。
挑一条最可能的用确定口气说出来，等于**教学习者去修一个他没有的毛病**。
原则：**要么能真的诊断，要么不上线。**

### 三种真诊断（都不是猜，且都能实现）

**① 听辨题（感知）—— 最便宜的真诊断**

"你听到的是 `Bett` 还是 `Beet`？"——客观对错，不需要 API。
听不出区别就一定发不出区别，而且感知先于产出，本来就该先测这个。

**② 最小对立对打分（产出）—— 把猜测变成测量**

`assessPronunciation({ audioBlob, referenceText })` 的参考文本是显式传入的，
`assessmentBlob` 也会保留。**同一段录音按两个参考文本各评一次，比较分数**：
`Beet` 得分高于 `Bett`，那就是你确实把短元音读长了——这是测量，不是猜。

代价是 2 倍 API 调用，所以**只在该格的目标音卡片上做**，或只在首次低分时做一次。

德语真实最小对立对（用真词，不用 `isch` 这类伪词——伪词的 G2P 打分不可靠）：

| 格 | 目标 | 对立对 |
|---|---|---|
| V1 | 元音长短 | `Bett`/`Beet` · `Stadt`/`Staat` · `Ofen`/`offen` |
| V2 | w vs v | `wir`/`vier` |
| V2 | ei vs ie | `Wein`/`Wien` · `Beine`/`Biene` |
| V3 | ç vs ʃ | `Kirche`/`Kirsche` |
| V4 | ü vs i | `Kiste`/`Küste` · `für`/`vier` |
| V4 | ö vs o | `schon`/`schön` |
| V6 | 词重音 | `úmfahren`/`umfáhren` |

**V5（硬起首等）找不到可靠对立对，那一格就只用 ① 和 ③，不硬凑。**

**③ 自己的录音 vs 标准音（自评）—— 已经有了**

`speakPractice` 的 `renderCompare` 已经实现了 A/B 回放。
这是正规发音训练的核心手段，而且它**不宣称任何它不知道的事**。

### 分数低但对立对没区分出来时

直接说："这个词 42 分。再对比一次你的录音和标准音。"
**不编原因。** 宁可信息少，不可给错方向。

### 每张卡仍然只针对一个音

不是为了猜错在哪，是为了让 ①②③ 三种诊断都有明确对象。
这也是发音课不能用长句跟读的原因：`Ich koche auch nicht.` 读砸了，无从下手。

### 形态：卡片流，不是可滚动的文章

用现有微步课外壳（`runLessonShell`）：一屏一个动作、进度条、答错重排队。
不是一页读完的文章 + 底下三道题。

## 三、英语同源词：是入口，不是路

英语基础者第一天就能被动认出几百个 A1 德语词（Wasser/water、Buch/book、trinken/drink…）。
这是**热情的开关**，别的 App 给不了。但直接当学习方法会造成混淆，所以限定用法：

### 四条硬规则

1. **只用在破冰期的一次性清单**——"你已经认识这些德语词了"，看完就结束。不是长期记词方法。
2. 之后这些词**照常进 SRS**，和其他词一样练，不留英语拐杖。
3. **假朋友单独成格，优先级高**——英语基础者必踩，是高价值教学内容，不是附录。
   `Gift`（毒药）· `bekommen`（得到）· `also`（所以）· `bald`（很快）· `Rock`（裙子）· `Handy`（手机）· `Chef`（老板）
4. **同源词的发音一律不许用英语类比**。发音陷阱恰好和同源关系重叠，这条必须是硬规则：
   `Wein`≠wine · `Vater`≠father（v=f）· `Zeit`≠tide。

## 四、内容生产：先给约束，再生成，再过闸

### 为什么已有内容偏难，不是 AI 写得差

现有 8 个精听包 + 14 篇精读的已知词率只有 37–60%。原因是**写的时候没有约束可用**：
全景图（该练哪格）、Goethe 词表（哪些词能用）、审计门禁（自动拦超纲）三样都是后来才建的。

### 生产流程

> **约束 → 生成 → 过闸 → 不合格重来**

输入约束举例：
> 学习者已会这 380 个词，这些语法格子已达标；
> 写一段 4 句对话，主题「点单」，只用这些词 + 最多 3 个新词，
> 每句 ≤7 词，不用从句（A1 无从句），不用第二格。

闸门**已经存在**（`tools/audit_a1_content.mjs` + `tools/a1-coverage.mjs`）：
超纲词 / 语法越界 / 已知词率 / 课程词复用率。原本用来审人写的内容，正好用来卡机器生成的。

离线批量跑，不需要后端、不联网调 AI、用户零成本。

### 已有内容怎么处理

- **精听精读 22 份：往下改简**，不重写——砍句子、换词、超纲词替成词表内的词。
  审计工具能直接给出每份差多少。
- **微步课：大概率没问题**——短、有技能标签、已接掌握度。
- **发音课：已确诊要重排**（见第二节）。
- 原则：**先用全景图和审计工具测量哪些内容跑偏，再动手**，不靠猜。

## 五、泛听泛读：目标是"证明你行"，不是教东西

长得像精听精读，目标完全不同。

| | 精听精读 | 泛听泛读 |
|---|---|---|
| 目标 | **准确**——每个词都抓住 | **自动化 + 速度**——不用想就懂 |
| 材料已知词 | ~92%，有新东西 | **≥98%**，几乎没新东西 |
| 行为 | 反复听、查词、听写 | 一遍过、不查词、允许没听全 |
| 度量 | 正确率 | **只记量**（今天读了 8 分钟） |

### 三条设计结论

1. **不进主线。** 主线有目标、有反馈、有对错；泛读的价值恰恰在于**没有压力和评分**——
   加了评分它就变成精读了。放仓库，用时长记，不记正确率。
2. **供给零成本**：做过的精听精读材料，隔几天重听重读一遍就是泛听泛读。
   **现有 22 份就是可用的泛听素材**，不需要任何新内容。
3. **它才是热情的主要来源**。精听练准确，会累；泛听是"我居然听懂了一整段德语"。
   学习者需要一个不会失败的地方。

### 对"下学期去德国"的额外价值：真实语速

精听用的是清晰录音，德国人不这么说话。泛听阶段应逐步引入正常语速、
乃至带背景噪音的版本——现有音频先加 1.0× / 1.15× 就能起步。
